Flows:

User Creation:
1) User enters username and password
2) credentials are stored to identity tables (password is stored as a random generated salt)
3) a new RSA key is generated
4) encryption of pvt-key:
	a. derivation key is generated by using KDF (argon2) --> using user's password + it's salt (see point 1)
	b. private key gets encrypted with the new argon2 key
	c. encrypted pvt key is stored in a DB table along with the userId (to retrieve the salted password)
	d. basically to "unlock" the private key user has to give the password as clear text and it will be combined with the argon2key salt stored previously, and in that way it will return the rsa pvt key

File encryption:
1) Sender Generates AES Key and Encrypts the File:
	a. The sender generates an AES key to encrypt the file.

2) Sender Encrypts AES Key with Recipient’s RSA Public Key:
	a. The sender uses the recipient’s RSA public key to encrypt the AES key.

3) Sender Sends Encrypted Data:
	The sender transmits:
		a. The AES-encrypted file.
		b. The RSA-encrypted AES key.

4) Recipient Decrypts AES Key:
	a. The recipient uses their RSA private key to decrypt the AES key.

5) Recipient Decrypts the File:
	a. The recipient then uses the decrypted AES key to decrypt the file.
